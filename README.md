# AI-Hub ops tracker: adoption, AI spend vs budget, agent governance (synthetic data)

Python, pandas, NumPy, matplotlib. All company data is synthetic and generated by the script; the problems in it are injected on purpose so the checks can be scored.

## Problem
A company rolling out Claude, Claude Code, n8n and internal agents needs to know, per team: who actually uses the tools, what it costs against budget, whether productivity moved against a frozen baseline, and whether any agent breaks the AI rulebook (usage levels human only / human in the loop / autonomous, least-privilege access, data classification).

## Data (generated)
- 6 teams, 120 employees, 90 days. Days 1-30 are the frozen baseline before rollout.
- Usage log of 11,394 rows, made messy on purpose: 3 date formats, costs as text ("$1.20", "USD 0.80", "1,50"), team names in mixed case and spacing, 5 % missing team, 3 % duplicate rows, a test bot account.
- Tasks closed per person per week; agent registry with owner, usage level, data scopes and read/write access.
- Injected problems: Engineering AI spend more than doubles from 10 November; Legal adoption stays low; an autonomous agent can write to confidential client contracts; an agent in the logs is missing from the registry.

## What it does
1. Cleans the log and reports each fix.
2. KPIs per team: active share, spend, cost per active user, tasks per person per week vs the frozen baseline.
3. Projects month-end spend from the last 14 days' run rate and flags teams above 110 % of budget; replays the check day by day to see when it would have warned.
4. Governance checks against the registry.
5. Writes an HTML report for non-technical readers (results/report.html), plus CSV and JSON.

## Run
    pip install -r requirements.txt
    python aiops_hub.py

## Results (results/run_log.json)
- Cleaning: 331 duplicates and 40 bot rows removed, 546 missing teams filled from the employee directory, 0 dates or costs left unparsed; 11,023 clean rows.
- Injected problems caught: 4 of 4, with 0 false flags.
- Spend drift: Engineering projected at 120 % of its November budget. Replayed daily, the check first warned on 18 November, 8 days after the drift started and 12 days before month end; no other team was flagged between 5 October and 29 November.
- Governance: found the unregistered agent (140 calls) and the autonomous agent with write access to client contracts. It also flagged a "human only" Legal agent that was being called. I did not inject that one; the simulation let Legal call it, and the check is right to flag it.
- Metric design: my first adoption metric was weekly active users / headcount. It saturated (anyone who used a tool once in a week counted), so Legal showed 55 % and was missed. Daily active share showed 16 % for Legal and 56-81 % for the other teams, and is the metric the flag now uses. Both are reported.
- Productivity: tasks per person per week rose 4-12 % in five teams and stayed flat in Legal (-0.1 %). This is a before/after comparison with no control group, so it is not a causal estimate of what AI changed.

## Limits
- Synthetic data: the checks are scored on problems I designed, so 4/4 shows the logic works, not how it performs on a real company.
- Run-rate projection is linear; a spike at month end would be missed until it happens.
- The code was written with an AI coding assistant and reviewed and run by me.
